### L1 · Build a looped transformer block: reuse weights to buy depth without parameters

`AI-off fluency` · now 2.5 → target 4.0 · priority 1.50 · ~15 min

**Why today.** Inkling 2 Mini is described as a looped transformer whose middle layers run several times per token, so its 26.4B parameters understate the compute it spends per token. ([Thinking Machines releases Inkling 2 Mini, a 26.4B open-weight looped MoE that runs on a laptop](https://thinkingmachines.ai/news/inkling-2-mini/))

A looped (weight-tied, or universal) transformer applies the same block f_theta R times: x_{r+1} = x_r + f_theta(x_r). Parameter count, and so weight memory, is fixed, while FLOPs and effective depth scale linearly with R, which lets a small model spend more serial computation per token, much like iterating a fixed-point solver. Training backpropagates through all R passes, so gradients for theta are summed over every pass, the same way gradients are shared across time steps in an RNN. That can make optimisation less stable: the residual stream norm grows with each pass, as the toy below shows, which is why pre-norm, careful initialisation or a learned exit or halting rule matter. The trade-off: loops buy depth cheaply in memory but not in latency, because the passes are sequential. The sizes below are illustrative and unrelated to any real model's configuration.

$$
x_{r+1} = x_r + f_\theta(x_r),\quad r = 0..R-1, \qquad |\theta| \text{ fixed}, \quad \text{FLOPs} \propto R \cdot 2|\theta| T
$$

```python
# Looped (weight-tied) residual block, stdlib only: one block reused R times.
# Parameters stay fixed while depth and FLOPs grow with R. Illustrative sizes only.
import math, random
random.seed(0)
d, T = 32, 8                                   # width, tokens

def mat(r, c, s): return [[random.gauss(0, s) for _ in range(c)] for _ in range(r)]
def mm(A, B): return [[sum(a * b for a, b in zip(row, col)) for col in zip(*B)] for row in A]
def ln(X): return [[(v - sum(r)/len(r)) / math.sqrt(sum((u - sum(r)/len(r))**2 for u in r)/len(r) + 1e-5) for v in r] for r in X]
def add(A, B): return [[a + b for a, b in zip(ra, rb)] for ra, rb in zip(A, B)]

Wq, Wk, Wv, Wo = (mat(d, d, d**-0.5) for _ in range(4))
W1, W2 = mat(d, 4*d, d**-0.5), mat(4*d, d, (4*d)**-0.5)

def attn(H):
    Q, K, V = mm(H, Wq), mm(H, Wk), mm(H, Wv)
    out = []
    for t in range(T):                          # causal: token t sees 0..t
        s = [sum(q*k for q, k in zip(Q[t], K[j])) / math.sqrt(d) for j in range(t + 1)]
        m = max(s); w = [math.exp(x - m) for x in s]; z = sum(w)
        out.append([sum(w[j]/z * V[j][i] for j in range(t + 1)) for i in range(d)])
    return mm(out, Wo)

def block(X):
    X = add(X, attn(ln(X)))
    return add(X, mm([[max(v, 0) for v in r] for r in mm(ln(X), W1)], W2))

params = 4*d*d + 2*4*d*d
X0 = mat(T, d, 1.0)
for R in (1, 2, 3):
    X = X0
    for _ in range(R):                          # the same weights on every pass
        X = block(X)
    flops = R * T * 2 * params                  # weight matmuls only
    norm = math.sqrt(sum(v*v for r in X for v in r))
    print(f"R={R}: params={params:,}  matmul FLOPs~{flops:,}  |X|={norm:.1f}")
```

### L2 · Put an interval on a canary hit rate, including the zero-hit case

`Experimental rigor` · now 4.5 → target 5.0 · priority 0.25 · ~10 min

**Why today.** OpenRouter's warning followed a Dragos study that seeded about two million prompts with canary links and watched which providers' links were later opened, which is a proportion-estimation problem. ([OpenRouter warns prompts routed to MiniMax, including 'zero data retention' traffic, may have been read](https://startupfortune.com/openrouter-warns-minimax-prompts-may-have-been-read-by-a-third-party/))

A canary study turns 'does this provider read prompts?' into counting k hits out of n planted canaries and estimating the rate p. The naive Wald interval p ± z·sqrt(p(1-p)/n) collapses to zero width when k = 0 and goes outside [0, 1] near the edges. The Wilson score interval inverts the score test instead, so it stays inside [0, 1] and keeps close to nominal coverage for small k. With zero hits the useful statement is an upper bound: the 'rule of three' gives p < 3/n at 95%, so clearing a provider at a 0.1% access rate needs about 3,000 clean canaries. Two caveats outweigh the arithmetic: canaries detect only access that triggers them (fetching a link), and hits that cluster in time or by endpoint violate the independence the interval assumes. The counts below are illustrative, not the study's data.

$$
\tilde p = \frac{\hat p + \frac{z^2}{2n}}{1+\frac{z^2}{n}}, \quad \text{half-width} = \frac{z\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}}}{1+\frac{z^2}{n}}, \qquad k=0 \Rightarrow p < 1-0.05^{1/n} \approx 3/n
$$

```python
# Canary study: how sure are you that a provider reads prompts?
# Wilson score interval for a proportion, plus the "zero hits" upper bound.
# Counts below are ILLUSTRATIVE, not the Dragos study's data.
from math import sqrt

def wilson(k, n, z=1.96):
    p = k / n
    c = (p + z*z/(2*n)) / (1 + z*z/n)
    h = z * sqrt(p*(1-p)/n + z*z/(4*n*n)) / (1 + z*z/n)
    return max(0.0, c - h), min(1.0, c + h)

for name, k, n in [("provider A", 0, 5000), ("provider B", 7, 5000), ("provider C", 40, 60)]:
    lo, hi = wilson(k, n)
    print(f"{name}: {k}/{n} canaries fired -> rate in [{lo:.4%}, {hi:.4%}] (95%)")

# Rule of three: with 0 hits in n trials the 95% upper bound is about 3/n.
for n in (100, 1000, 100000):
    print(f"0 hits in {n:>6}: rate < {3/n:.4%}  (exact: {1 - 0.05**(1/n):.4%})")
```
