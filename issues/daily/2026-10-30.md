### L1 · Report a kernel speedup honestly: ratio, latency cut and a bootstrap interval

`LLM / agent evaluation` · now 2.5 → target 4.5 · priority 2.00 · ~10 min

**Why today.** The story quotes 472 us against 518 us as a 9.8% gain, from a single livestream run. ([ModelBest's ForgeKernel agent writes an attention kernel 9.8% faster than DeepSeek's FlashMLA Prefill on B200](https://www.qbitai.com/2026/10/506785.html))

A speedup and a latency reduction are different numbers: 518/472 - 1 is about 9.7% faster, while 1 - 472/518 is about 8.9% less time. Quote which one you mean. A single timing also hides run-to-run noise from clocks, caches and scheduling, so repeat the measurement and bootstrap the ratio of mean latencies to get an interval. If the interval for 'B is faster than A' includes zero, the claim is not established. The snippet uses simulated, illustrative latencies centred on the reported figures; it is not ModelBest's data.

$$
s = \frac{\bar t_A}{\bar t_B} - 1,\quad c = 1 - \frac{\bar t_B}{\bar t_A}
$$

```python
import random, statistics as st
random.seed(0)
# Illustrative latencies in microseconds (NOT ModelBest's data): kernel A ~518 us, kernel B ~472 us
a = [random.gauss(518, 12) for _ in range(30)]
b = [random.gauss(472, 12) for _ in range(30)]
print("latency cut: %.1f%%" % (100 * (1 - st.mean(b) / st.mean(a))))
print("speedup (a/b - 1): %.1f%%" % (100 * (st.mean(a) / st.mean(b) - 1)))
def boot():
    ra = [random.choice(a) for _ in a]; rb = [random.choice(b) for _ in b]
    return st.mean(ra) / st.mean(rb) - 1
xs = sorted(boot() for _ in range(2000))
print("95%% CI speedup: %.1f%% .. %.1f%%" % (100 * xs[50], 100 * xs[1949]))
```

### L2 · Write causal softmax attention from scratch, and check a one-line invariant

`AI-off fluency` · now 2.5 → target 4.0 · priority 1.50 · ~15 min

**Why today.** The reported kernel targets a prefill attention path, the computation below in its plainest form. ([ModelBest's ForgeKernel agent writes an attention kernel 9.8% faster than DeepSeek's FlashMLA Prefill on B200](https://www.qbitai.com/2026/10/506785.html))

Attention for query i is a softmax over scaled dot products with keys 0..i, then a weighted sum of values. Subtracting the row maximum before exponentiating keeps exp from overflowing without changing the result. Causality means the first token can only attend to itself, so its output must equal V[0] exactly, a cheap invariant to test any optimised kernel against a slow reference. Real kernels fuse these steps and tile them through on-chip memory; the maths is unchanged. Sizes here are illustrative.

$$
o_i = \sum_{j\le i} \mathrm{softmax}_j\!\left(\frac{q_i\cdot k_j}{\sqrt d}\right) v_j
$$

```python
import math, random
random.seed(1)
T, d = 4, 8
Q = [[random.gauss(0, 1) for _ in range(d)] for _ in range(T)]
K = [[random.gauss(0, 1) for _ in range(d)] for _ in range(T)]
V = [[random.gauss(0, 1) for _ in range(d)] for _ in range(T)]
def attn(Q, K, V):
    out = []
    for i, q in enumerate(Q):
        s = [sum(x * y for x, y in zip(q, K[j])) / math.sqrt(d) for j in range(i + 1)]  # causal
        m = max(s); e = [math.exp(x - m) for x in s]; z = sum(e)
        out.append([sum(e[j] / z * V[j][c] for j in range(i + 1)) for c in range(d)])
    return out
o = attn(Q, K, V)
print("row0 equals V[0]:", all(abs(a - b) < 1e-12 for a, b in zip(o[0], V[0])))
print("out[3][:3] =", [round(x, 3) for x in o[3][:3]])
```
