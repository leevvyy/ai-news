### L1 · Why a world model's rollout error compounds, and how to measure it

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~15 min

**Why today.** Baidu's Apollo World is described as a world model for physical AI, and a world model is only useful if its multi-step predictions stay accurate. ([Baidu unveils Apollo World, an agent-driven multimodal world model for physical AI, already used in Apollo Go testing](https://www.ithome.com/1/021/808.htm))

A world model is trained to predict the next state from the current one, usually with teacher forcing: it always sees the true previous state. At use time it must feed on its own predictions, so a small one-step error is re-applied at every step. With an unstable or marginally stable system the error grows roughly geometrically; in this toy, stable dynamics make it saturate instead. The numbers are illustrative and say nothing about Baidu's model. Evaluate with open-loop rollouts at several horizons, not only one-step loss, and consider training on the model's own rollouts to close the gap.

$$
e_h = |x_h - \hat{x}_h|, \quad \hat{x}_{h+1} = f_\theta(\hat{x}_h)
$$

```python
import random
random.seed(0)
# Toy 1-D world model: true dynamics x' = 0.95x + noise; learned model has 3% slope error.
a_true, a_hat = 0.95, 0.98
def rollout(h, trials=2000):
    err = 0.0
    for _ in range(trials):
        x = xh = 1.0
        for _ in range(h):
            x = a_true * x + random.gauss(0, 0.02)
            xh = a_hat * xh           # model feeds on its own predictions
        err += abs(x - xh)
    return err / trials
for h in (1, 5, 20, 50):
    print(h, round(rollout(h), 4))
```
