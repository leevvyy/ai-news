### L1 · Read log-perplexity correctly, and normalise it to bits per byte across tokenizers

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~15 min

**Why today.** Pachocki proposed industry limits keyed to perplexity, quoting log-perplexities of about 0.99 for GPT-3.5 and 0.91 for GPT-4, while conceding perplexity is hard to compare across labs. ([OpenAI chief scientist Pachocki proposes industry-wide AI development limits tied to perplexity](https://www.bloomberg.com/news/articles/2026-11-22/openai-chief-scientist-urges-industry-limits-on-ai-development))

Log-perplexity is the average negative log-likelihood the model assigns to held-out tokens, i.e. cross-entropy in nats per token; perplexity is its exponential, the effective number of equally likely choices per token. Because it is averaged per token, it depends on the tokenizer: a tokenizer that cuts text into more, smaller pieces makes each token easier to predict, lowering per-token loss without the model compressing the text any better. Dividing by ln 2 and by the average bytes per token gives bits per byte, which measures compression of the raw text and is comparable across tokenizers (given the same evaluation text). It still depends on the evaluation distribution and on contamination, and it says nothing about gains from reasoning at inference time, since chain-of-thought tokens are generated rather than scored. The toy below shows a model with lower per-token log-perplexity that is worse in bits per byte; all numbers are illustrative.

$$
\log \mathrm{PPL} = -\frac{1}{N}\sum_{t=1}^{N} \ln p_\theta(x_t \mid x_{<t}), \qquad \mathrm{BPB} = \frac{N \cdot \log \mathrm{PPL}}{B \ln 2}
$$

```python
# Log-perplexity is cross-entropy in nats per token; it depends on the tokenizer.
# Convert to bits per byte (BPB) to compare models with different tokenizers.
# All numbers are illustrative, not any real model's figures.
import math, random
random.seed(0)

def log_ppl(probs):                     # probs the model gave the observed tokens
    return -sum(math.log(p) for p in probs) / len(probs)

def bits_per_byte(lp_nats_per_tok, bytes_per_tok):
    return lp_nats_per_tok / math.log(2) / bytes_per_tok

text_bytes = 10_000
# Model A: coarse tokenizer (4.0 bytes/token). Model B: fine tokenizer (3.0 bytes/token).
for name, bpt, mean_p in [("A", 4.0, 0.42), ("B", 3.0, 0.50)]:
    n_tok = int(text_bytes / bpt)
    probs = [min(0.999, max(1e-4, random.gauss(mean_p, 0.15))) for _ in range(n_tok)]
    lp = log_ppl(probs)
    print(f"model {name}: tokens={n_tok:5d} log-ppl={lp:.3f} nats/tok "
          f"ppl={math.exp(lp):.2f}  BPB={bits_per_byte(lp, bpt):.3f}")
# B has the lower log-ppl per token, yet A spends fewer bits per byte of text.
for lp in (0.99, 0.91, 0.76):
    print(f"log-ppl {lp:.2f} -> ppl {math.exp(lp):.3f}")
```

### L2 · Detect benchmark contamination with n-gram overlap before trusting an exam score

`LLM / agent evaluation` · now 2.5 → target 4.5 · priority 2.00 · ~15 min

**Why today.** China's TCM licensing exam centre says material sold to train or evaluate models as 'past papers' or 'internal question banks' did not come from it, and that it never tested any model. ([China's TCM licensing exam centre says it never released past papers or tested any AI model, warns over marketing claims](https://www.thepaper.cn/newsDetail_forward_34530585))

A score on an exam-style benchmark only measures generalisation if the test items, or close paraphrases, were not in the training data. The standard first check is n-gram overlap: tokenise each test item, take its set of long n-grams (13 words is a common choice) and measure what fraction also appear in the training corpus; items above a threshold are flagged and the score is reported on the clean subset as well. Long n-grams make chance matches rare, so high overlap almost always means the item was seen. It misses paraphrases, translations and reformatted questions, which need embedding similarity or model-based probes such as checking whether the model completes a question verbatim or prefers the original over a reworded version. When the training data is unknown, as with a vendor claim, the honest move is to evaluate on fresh items written after the model's cutoff. The strings below are toy examples.

$$
\mathrm{overlap}(q) = \frac{|G_{13}(q) \cap G_{13}(\mathcal{D}_{train})|}{|G_{13}(q)|}
$$

```python
# Benchmark contamination check: share of each test item's word 13-grams that also
# appear in a training corpus. Toy strings, illustrative only.
def ngrams(text, n=13):
    w = text.lower().split()
    return {tuple(w[i:i + n]) for i in range(len(w) - n + 1)}

train_docs = [
    "a patient presents with fever thirst and a rapid floating pulse which pattern "
    "best describes the presentation according to the classical texts on exterior conditions",
    "unrelated web text about stock markets and chips falling sharply in a broad sell off "
    "across asia on friday afternoon trading sessions",
]
test_items = [
    "q1: a patient presents with fever thirst and a rapid floating pulse which pattern "
    "best describes the presentation according to the classical texts",
    "q2: a patient reports chronic fatigue cold limbs and a deep slow pulse what is "
    "the most appropriate treatment principle in this case",
]
train_grams = set().union(*(ngrams(d) for d in train_docs))
for item in test_items:
    g = ngrams(item)
    overlap = len(g & train_grams) / max(1, len(g))
    flag = "CONTAMINATED" if overlap > 0.5 else "clean"
    print(f"{item[:3]} 13-gram overlap {overlap:.0%} -> {flag}")
```
