### L1 · Fit a hinge regression to find where a training-loss trend breaks

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~15 min

**Why today.** METR fitted a two-segment trend to OpenAI's log-perplexity data and reports the decline speeding up from about 0.022 to about 0.156 per year after a February 2026 breakpoint. ([METR analyses OpenAI's published loss data: pretraining loss falling about 7x faster since early 2026](https://metr.org/blog/2026-11-24-interpreting-a-recent-acceleration-in-pretraining-loss/))

A hinge (segmented) regression models y = a + b1 t + b2 max(0, t - tau), so the slope is b1 before tau and b1 + b2 after it, with the curve continuous at tau. For a fixed tau this is ordinary least squares, so you can grid-search tau and keep the fit with the lowest squared error. The catch is that tau is chosen to fit the data: with few points (METR had 13 models), the breakpoint and the post-break slope have wide, non-Gaussian uncertainty, and a smooth acceleration or one outlier near the end can look like a sharp break. Report a bootstrap or profile-likelihood interval for tau and the slope ratio, and compare the fit against a single line and a smooth curve with an information criterion before calling it a regime change. The snippet uses synthetic data, not OpenAI's numbers.

$$
y_i = a + b_1 t_i + b_2 \max(0, t_i-\tau) + \varepsilon_i,\quad \hat\tau = \arg\min_\tau \mathrm{SSE}(\tau)
$$

```python
# Fit a two-segment (hinge) linear trend to log-loss vs time and find the breakpoint.
# Synthetic, illustrative data only (not OpenAI's or METR's numbers).
import random
random.seed(0)
t = [2022 + 0.25 * i for i in range(20)]              # years
true_bp, a, s1, s2 = 2026.1, 1.20, -0.02, -0.15
y = [a + s1 * (x - 2022) + (s2 - s1) * max(0.0, x - true_bp) + random.gauss(0, 0.01) for x in t]

def ols(X, y):  # tiny normal-equations solver for 3 params
    n = len(X[0]); A = [[sum(r[i] * r[j] for r in X) for j in range(n)] for i in range(n)]
    b = [sum(r[i] * yy for r, yy in zip(X, y)) for i in range(n)]
    for i in range(n):  # Gaussian elimination
        for k in range(i + 1, n):
            f = A[k][i] / A[i][i]
            A[k] = [ak - f * ai for ak, ai in zip(A[k], A[i])]; b[k] -= f * b[i]
    c = [0.0] * n
    for i in reversed(range(n)):
        c[i] = (b[i] - sum(A[i][j] * c[j] for j in range(i + 1, n))) / A[i][i]
    return c

best = None
for bp in [2023 + 0.05 * k for k in range(70)]:
    X = [[1.0, x - 2022, max(0.0, x - bp)] for x in t]
    c = ols(X, y)
    sse = sum((yy - sum(ci * xi for ci, xi in zip(c, r))) ** 2 for r, yy in zip(X, y))
    if best is None or sse < best[0]:
        best = (sse, bp, c)
sse, bp, c = best
print(f"breakpoint ~ {bp:.2f}; slope before {c[1]:.3f}/yr, after {c[1]+c[2]:.3f}/yr, ratio {(c[1]+c[2])/c[1]:.1f}x")
```

### L2 · Work out the real bits per weight of a ternary model, scales included

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~10 min

**Why today.** PrismML says Ternary Bonsai 2.5 27B averages about 1.76 bits per weight and fits in roughly 5.9 GB. ([PrismML releases Ternary Bonsai 2.5 27B, a 5.9 GB open-weight ternary model tuned for coding agents and tool use](https://prismml.com/news/bonsai-2-5-27b))

A ternary weight takes one of {-1, 0, +1}, so its information content is log2 3 ≈ 1.585 bits. Real formats need byte-friendly packing: 5 trits fit in one byte because 3^5 = 243 ≤ 256, which gives 1.6 bits. Each group of weights also needs a higher-precision scale, adding scale_bits/group bits per weight. Layers kept at higher precision, such as embeddings, norms and the output head, push the average up further. That is why reported figures land a little above 1.585. Memory is roughly params × bits / 8 bytes plus the KV cache and activations, so a weight-only number understates what inference needs. The group size and scale format in the snippet are assumptions, not PrismML's spec.

$$
b_{\text{eff}} = \tfrac{8}{5} + \tfrac{s}{G} \;\ge\; \log_2 3,\qquad M \approx N\,b_{\text{eff}}/8
$$

```python
# Bits per weight of a ternary model, and what fits in memory.
# Illustrative arithmetic; group size and scale format are assumptions, not PrismML's spec.
import math
params = 27e9
ideal = math.log2(3)                       # entropy bound for {-1, 0, +1}
packed = 8 / 5                             # 5 trits per byte: 3^5 = 243 <= 256
group, scale_bits = 128, 16                # one fp16 scale per 128 weights (assumed)
eff = packed + scale_bits / group
for name, b in [("fp16", 16), ("int4", 4 + 16 / 128), ("ternary, ideal", ideal),
                ("ternary, 5-per-byte + scales", eff)]:
    print(f"{name:30s} {b:6.3f} bits/w  -> {params * b / 8 / 1e9:6.2f} GB")
print("reported: ~1.76 bits/w, ~5.9 GB ->", round(params * 1.76 / 8 / 1e9, 2), "GB")
```

### L3 · Predict 'all k variants correct' accuracy from per-prompt accuracy

`LLM / agent evaluation` · now 2.5 → target 4.5 · priority 2.00 · ~10 min

**Why today.** Humanity's First Exam counts a family of four near-identical prompts only if all four are right; top models score 96-98% on single prompts but average 85.6% at family level. ([Google DeepMind releases 'Humanity's First Exam', a 544-prompt test of whether models answer easy questions reliably](https://www.ventureatlas.org/news/2026-11-24-deepmind-humanitys-first-exam))

If errors were independent with per-prompt accuracy p, a family of k variants would pass with probability p^k, so 0.97^4 ≈ 0.885. Errors are usually correlated within a family: if a model can't do the task, it misses all variants. For a fixed mean p, this concentration raises family accuracy above p^k (by Jensen's inequality on q ↦ q^k), up to p when errors cluster completely. So a family score at or below p^k means the model is failing variants it 'should' get right, which is exactly the inconsistency the metric targets. Repeated runs add sampling noise as another source of variation. The snippet uses illustrative numbers, not HFE data.

$$
P_{\text{fam}} = \mathbb{E}[q^k] \;\ge\; (\mathbb{E}[q])^k = p^k
$$

```python
# Family-level ('all k variants right') accuracy vs per-prompt accuracy p.
# Illustrative numbers only. Families are a mix of easy and hard ones with the same mean accuracy p.
p, k = 0.97, 4
print(f"independent errors: p^k = {p**k:.3f}")
for f_hard in (0.03, 0.06, 0.15, 0.5):           # share of families that are 'hard'
    q_hard = 0.0 if f_hard <= 1 - p else 1 - (1 - p) / f_hard   # hard-family accuracy
    q_hard = max(q_hard, 0.0)
    q_easy = (p - f_hard * q_hard) / (1 - f_hard) if f_hard < 1 else p
    if q_easy > 1: continue
    fam = f_hard * q_hard**k + (1 - f_hard) * q_easy**k
    print(f"hard share {f_hard:.2f}: q_hard={q_hard:.2f} q_easy={q_easy:.3f} -> family pass {fam:.3f}")
# Monte Carlo check of the independent case
import random; random.seed(1)
n = 100_000
mc = sum(all(random.random() < p for _ in range(k)) for _ in range(n)) / n
print(f"Monte Carlo (independent): {mc:.3f}")
```
