### L1 · Size a KV cache, and reject what does not fit

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~15 min

**Why today.** Cloudflare's GLM-5.3 leak started with a 1,048,576-token context window served from a KV pool that held 681,280 tokens. ([Cloudflare: GLM-5.3 KV-cache bug exposed other customers' data in 155 Workers AI responses](https://blog.cloudflare.com/kv-cache-exposure-remediation/))

During decoding a transformer caches the key and value vectors of every past token in every layer, so attention does not recompute them. That cache, not the weights, is what limits context length and batch size in serving. Its size is linear in layers, KV heads, head dimension, tokens and batch. Grouped-query attention (GQA) shrinks it by sharing each KV head across several query heads. A server must admit a request only if prompt plus generation fits in the pool; anything else has to be rejected, never silently rewritten.

$$
M_{KV} = 2 \cdot L \cdot n_{kv} \cdot d_{head} \cdot T \cdot b \cdot \text{bytes}
$$

```python
def kv_cache_bytes(layers, n_kv_heads, head_dim, tokens, batch=1, bytes_per=2):
    """K and V for every layer: 2 * n_kv_heads * head_dim values per token (bf16 = 2 bytes)."""
    return 2 * layers * n_kv_heads * head_dim * tokens * batch * bytes_per

# Illustrative GQA config, not GLM-5.3's: 60 layers, 8 KV heads, head_dim 128, bf16
cfg = dict(layers=60, n_kv_heads=8, head_dim=128)
per_token = kv_cache_bytes(**cfg, tokens=1)
pool_tokens = 160 * 2**30 // per_token          # a 160 GiB KV pool
print(f"{per_token / 2**10:.0f} KiB/token -> pool holds {pool_tokens:,} tokens")

def admit(prompt_tokens, max_new_tokens, pool_tokens):
    need = prompt_tokens + max_new_tokens
    if need > pool_tokens:  # the Cloudflare bug: this case was swapped for a placeholder instead
        raise ValueError(f"needs {need:,} KV slots > pool {pool_tokens:,}: reject the request")
    return need

for T in (200_000, 1_048_576):
    try:
        print(f"{T:>9,} admitted, {admit(T, 4_096, pool_tokens):,} slots")
    except ValueError as err:
        print(f"{T:>9,} {err}")
```

### L2 · pass@k, pass^k and why one claimed success is not a rate

`LLM / agent evaluation` · now 2.5 → target 4.5 · priority 2.00 · ~20 min

**Why today.** OpenAI claims three major proofs, and none has been independently verified yet. ([OpenAI claims AI-generated proofs in math, computer science and physics; none independently verified](https://qz.com/openai-ai-discoveries-math-computer-science-physics-102726))

Agent and reasoning benchmarks report pass@k: the chance that at least one of k attempts passes a verifier. It rewards breadth and grows quickly with k. pass^k asks that all k attempts pass, which measures reliability and falls quickly. Both need a deterministic verifier and n > k attempts; the unbiased estimators below use combinations rather than plugging c/n into a power. A Wilson interval shows how little 10 attempts pin down. A single unverified claim gives you n = 1 and an unknown c.

$$
\text{pass@}k = 1 - \binom{n-c}{k}\Big/\binom{n}{k}, \qquad \text{pass}^k = \binom{c}{k}\Big/\binom{n}{k}
$$

```python
from math import comb, sqrt

def pass_at_k(n, c, k):
    """P(at least one of k draws passes), unbiased from n attempts with c passes (Chen et al., 2021)."""
    return 1.0 if n - c < k else 1 - comb(n - c, k) / comb(n, k)

def pass_hat_k(n, c, k):
    """P(all k draws pass): consistency, the metric that punishes lucky single successes."""
    return comb(c, k) / comb(n, k)

def wilson(c, n, z=1.96):
    p = c / n
    centre, half = p + z * z / (2 * n), z * sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return (centre - half) / (1 + z * z / n), (centre + half) / (1 + z * z / n)

# A model attempts a task family 10 times; independent checkers verify 3 of them
n, c = 10, 3
for k in (1, 3, 5):
    print(f"k={k}: pass@k={pass_at_k(n, c, k):.3f}  pass^k={pass_hat_k(n, c, k):.3f}")
lo, hi = wilson(c, n)
print(f"success rate 95% Wilson CI: [{lo:.2f}, {hi:.2f}]")
print("one unverified claim: n=1, c unknown -> no estimate at all")
```

### L3 · Turn a compute budget into a model size with C ≈ 6ND

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~15 min

**Why today.** Anthropic's S-1 shows hundreds of billions of dollars of compute commitments, and Oracle is scaling to multi-gigawatt clusters. ([Anthropic S-1 discloses $540-570B of compute commitments and plans for its own data centers](https://fortune.com/2026/10/26/anthropics-s1-ipo-reveals-the-inner-workings-of-its-fast-evolving-compute-strategy/) · [Oracle adds Google TPUs, Cerebras and SambaNova chips while expanding Nvidia Vera Rubin to multi-gigawatt scale](https://nvidianews.nvidia.com/news/nvidia-and-oracle-expand-nvidia-vera-rubin-to-multi-gigawatt-scale-and-bring-nvidia-vera-cpu-to-oracle-cloud-infrastructure))

Training a dense transformer costs about 6 FLOPs per parameter per token: 2 for the forward pass and 4 for the backward pass. Hoffmann et al. (Chinchilla) found that, for a fixed budget, loss is minimised with roughly 20 training tokens per parameter, so the optimal N and D both grow as the square root of C. Turning GPUs into FLOPs needs utilisation (MFU), which is usually 30-50% of peak. The numbers below are illustrative and are not any lab's actual cluster.

$$
C \approx 6ND, \quad D^\star \approx 20N^\star \;\Rightarrow\; N^\star \approx \sqrt{C/120}
$$

```python
# Illustrative numbers, not any lab's actual cluster
gpus, days = 10_000, 30
peak_flops = 989e12       # H100 dense BF16 peak, FLOP/s
mfu = 0.40                # model FLOPs utilisation actually achieved

C = gpus * days * 86_400 * peak_flops * mfu       # training compute, FLOPs
# Chinchilla rule of thumb: C ≈ 6 N D and compute-optimal D ≈ 20 N  =>  N = sqrt(C / 120)
N = (C / 120) ** 0.5
D = 20 * N
print(f"C = {C:.2e} FLOPs -> N ≈ {N / 1e9:.0f}B params, D ≈ {D / 1e12:.1f}T tokens")

for mult in (0.1, 1, 10):  # how the optimum moves with budget: N, D ∝ C^0.5
    n = (mult * C / 120) ** 0.5
    print(f"{mult:>4}x budget: N ≈ {n / 1e9:6.0f}B, D ≈ {20 * n / 1e12:5.1f}T")
```
