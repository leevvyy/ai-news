### L1 · Mask the SFT loss to assistant tokens when tuning tool calling

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~10 min

**Why today.** Huawei says openPangu-2.1-Pro's tool selection and calling were tuned on more than 100,000 specialised samples, which is supervised fine-tuning on multi-turn traces. ([Huawei Cloud launches openPangu-2.1-Pro flagship model on its MaaS platform, tuned for agents and HarmonyOS coding](https://www.ithome.com/1/027/450.htm))

A tool-use training example interleaves a system prompt with tool schemas, a user turn, the assistant's tool call, the tool's output and the final answer. Only the assistant spans are behaviour you want to teach, so the cross-entropy is averaged over those tokens and every other position gets a zero weight. Without the mask, most of the loss (and gradient) comes from predicting user text and tool outputs, which are noisy, long and not under the model's control, so the model learns to imitate tool responses instead of to call tools well. The mask also changes the normalisation: averaging over assistant tokens only means short tool calls are not drowned out by long tool outputs. It breaks down when the tool output itself must be parsed into structured state the model later relies on; some recipes then add a small weight on those tokens rather than zero.

$$
\mathcal{L} = -\frac{\sum_t m_t \log p_\theta(x_t\mid x_{<t})}{\sum_t m_t},\quad m_t = \mathbb{1}[\text{token } t \text{ is assistant-authored}]
$$

```python
import math
# Toy SFT example for tool calling: per-token log-probs the model assigns to the target token.
# Roles: S=system/tool schema, U=user, A=assistant (tool call + answer), T=tool output.
roles  = list("SSSSUUUUAAAATTTTTAAA")
logp   = [-0.1,-0.2,-0.1,-0.3, -2.0,-1.5,-2.2,-1.8, -0.9,-0.4,-0.2,-0.6,
          -3.0,-2.5,-2.8,-3.1,-2.9, -0.7,-0.5,-0.3]   # illustrative numbers
def nll(mask):
    picked = [-lp for lp, m in zip(logp, mask) if m]
    return sum(picked) / len(picked), len(picked)
full = nll([True] * len(roles))
asst = nll([r == "A" for r in roles])
print(f"loss on all tokens      : {full[0]:.3f} over {full[1]} tokens")
print(f"loss on assistant only  : {asst[0]:.3f} over {asst[1]} tokens")
# Gradient share: fraction of the summed loss that comes from tokens the model never has to produce
waste = sum(-lp for lp, r in zip(logp, roles) if r != "A") / sum(-lp for lp in logp)
print(f"share of unmasked loss from user/tool tokens: {waste:.0%}")
```

### L2 · Turn a Linpack exaflops figure into training days, and see why it misleads

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~10 min

**Why today.** China's HPC TOP100 put the Lingsheng system first at 2.198 EFlops Linpack, a number often read as AI-training capacity. ([China's 2026 HPC TOP100 list puts Shenzhen's Lingsheng supercomputer first at 2.198 exaflops](https://www.sina.cn/weibo/detail/5365667651912813.html))

Training compute for a dense transformer is about C = 6ND FLOPs (N parameters, D tokens: 2ND forward, 4ND backward). Wall-clock time is C divided by sustained throughput, which is peak FLOP/s times model FLOPs utilisation (MFU, typically 30-50% at scale). Linpack Rmax is measured in FP64 on dense linear algebra, while training runs in BF16 or FP8, where accelerators can be an order of magnitude or more faster, so plugging Rmax in directly overstates training time; the uplift factor depends entirely on the hardware and is an assumption in the snippet. Interconnect bandwidth, memory capacity and failure rates then decide whether the MFU you assume is reachable, which is why HPL rank is a weak proxy for AI capacity. The numbers below are illustrative, not a claim about any real machine or model.

$$
T = \frac{6ND}{P_{\text{peak}}\cdot \text{MFU}}
$$

```python
# Back-of-envelope: how long would a training run take on a machine of a given Linpack score?
# Illustrative model size and token count; HPL Rmax is FP64, AI training runs in BF16/FP8.
N = 1e12          # parameters (dense, illustrative)
D = 20e12         # training tokens (illustrative)
C = 6 * N * D     # training FLOPs, the 6ND rule for a dense transformer
rmax_fp64 = 2.198e18          # FLOP/s, Linpack Rmax quoted for the system
for label, peak in [("FP64 Rmax as-is", rmax_fp64),
                    ("x16 low-precision uplift (assumed)", rmax_fp64 * 16)]:
    for mfu in (0.3, 0.5):
        days = C / (peak * mfu) / 86400
        print(f"{label:36s} MFU={mfu:.0%}: {days:10.1f} days")
print(f"C = {C:.2e} FLOPs")
```
