### L1 · Separate parameters from compute: what weight-shared looping buys and costs

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~15 min

**Why today.** Zhipu's GLM-5.4 is reported to run a block of 28 GLM-5 layers twice per token with shared weights, which Z.ai says gives reasoning comparable to much larger models. ([Zhipu launches GLM-5.4, its first Loop Transformer flagship, on its Coding Plan with no benchmarks or API yet](https://www.thepaper.cn/newsDetail_forward_34539134))

A looped Transformer applies the same stack of layers k times, so effective depth grows k-fold while the parameter count (and the weight memory) stays fixed. Per-token compute is roughly 2 FLOPs per weight per executed layer, so it scales with effective depth, not with unique parameters; the KV cache also grows with every executed layer unless the loops share or drop their caches. The bet is that depth, i.e. more sequential refinement of the residual stream, matters more for reasoning than extra unique weights, while being cheaper to store and serve on scarce accelerators. It breaks where knowledge capacity matters: shared weights store fewer facts than the same compute spent on unique layers, and training a looped stack can be less stable because one gradient sums the contributions of every pass. Compare models at matched FLOPs per token and matched parameters, not on parameter count alone. The sizes in the snippet are illustrative.

$$
P = L_u\,(4d^2 + 2 m d^2), \qquad C_{tok} pprox k L_u\,(2 P_{block} + 4 T d), \qquad M_{KV} = 2 k L_u d \cdot b
$$

```python
# Looped (weight-shared) Transformer: depth costs FLOPs, not parameters.
# Illustrative sizes only, not any real model's configuration.
def block_params(d, ffn_mult=4):
    attn = 4 * d * d                 # Q, K, V, O projections
    ffn = 2 * d * (ffn_mult * d)     # up + down projections (dense FFN)
    return attn + ffn

def per_token_flops(d, layers_run, ctx, ffn_mult=4):
    # ~2 FLOPs per weight per token, plus attention score/value mixing over ctx
    return layers_run * (2 * block_params(d, ffn_mult) + 4 * ctx * d)

d, ctx, unique = 8192, 32_768, 28
for loops in (1, 2, 3):
    p = unique * block_params(d)
    f = per_token_flops(d, unique * loops, ctx)
    kv = 2 * unique * loops * d * 2   # bytes/token for K and V at bf16, one cache per executed layer
    print(f"loops={loops}: params={p/1e9:6.1f}B  effective depth={unique*loops:3d}  "
          f"GFLOPs/token={f/1e9:7.1f}  KV bytes/token={kv/1e6:5.2f} MB")
print("Weights stay fixed; compute and KV cache scale with the loop count.")
```

### L2 · Compute an abnormal return with a market model, and see where it misleads

`Domain AI (finance, health)` · now 3.5 → target 4.5 · priority 0.70 · ~12 min

**Why today.** Nvidia closed up about 31.5% on the day the Nasdaq rose about 6.5%, and this issue's market read-through measures exactly how much of a move like that is abnormal. ([Nasdaq jumps 6.5% in its best day since April 2025 as Nvidia soars 31% and chip stocks rally](https://finance.yahoo.com/markets/live/stock-market-today-monday-november-23-dow-sp-500-nasdaq-surge-after-nvidia-reinstates-jensen-huang-182039397.html) · [Nvidia's board unanimously reinstates Jensen Huang as CEO, 11 days after his resignation](https://nvidianews.nvidia.com/news/nvidia-board-reinstates-jensen-huang-as-president-ceo-and-board-director))

The market model regresses a stock's daily return on the index's over an estimation window that ends before the event, giving alpha and beta; the abnormal return on the event day is the actual return minus alpha plus beta times the market return. Dividing by the residual standard deviation gives a rough t-statistic, and summing over a few days gives a cumulative abnormal return (CAR). It works when the event is specific to the firm and the market move is independent of it. It breaks when the firm is a large index weight or the event moves the whole sector: then the market return contains the news, beta absorbs part of the effect, and the abnormal return is understated. That is the case on a day when one stock's news lifts the index, as the snippet's caveat notes. The data are synthetic except for the two day-0 returns.

$$
AR_t = R_{i,t} - (\hatlpha + \hateta R_{m,t}), \qquad t pprox rac{\sum_{s=0}^{n-1} AR_s}{\hat\sigma\sqrt{n}}
$$

```python
# Market-model abnormal return: how much of a stock's move is not explained by the market?
# Synthetic data; the day-0 returns echo the reported Nov 23 moves (NVDA ~+31.5%, Nasdaq ~+6.5%).
import random, statistics as st
random.seed(1)
n = 60
rm = [random.gauss(0.0005, 0.012) for _ in range(n)]          # market returns, estimation window
ri = [0.001 + 1.8 * m + random.gauss(0, 0.02) for m in rm]     # stock with true beta 1.8
mx, my = st.mean(rm), st.mean(ri)
beta = sum((x - mx) * (y - my) for x, y in zip(rm, ri)) / sum((x - mx) ** 2 for x in rm)
alpha = my - beta * mx
resid = [y - (alpha + beta * x) for x, y in zip(rm, ri)]
sigma = (sum(e * e for e in resid) / (n - 2)) ** 0.5
R_i, R_m = 0.315, 0.065                                        # event day
ar = R_i - (alpha + beta * R_m)
print(f"beta={beta:.2f} alpha={alpha:.4f} sigma={sigma:.4f}")
print(f"expected {alpha + beta*R_m:+.3f}, actual {R_i:+.3f}, AR={ar:+.3f}, t={ar/sigma:.1f}")
print("Caveat: the market's own +6.5% partly WAS the Nvidia news (NVDA is a big index weight).")
```

### L3 · Build a least-privilege tool gate for an agent: allowlist, budget, approval, audit

**Why today.** Reuters reports that US banks are isolating their internal agents, capping how much work they can do, giving them employee-style permissions and logging which systems they touched and whether a human approved. ([Reuters: some US banks tighten controls on in-house AI agents over fears of models escaping safeguards](https://www.bnnbloomberg.ca/business/artificial-intelligence/2026/11/23/some-us-banks-tighten-ai-agent-controls-on-concern-about-models-escaping-safeguards-reuters-exclusive/))

Agent controls belong in the harness, not in the prompt: every tool call passes through a gate that the model cannot rewrite. The gate checks four things in order: the tool is allowlisted for this task, a per-task budget is not exhausted, risky actions have an out-of-band human (or policy) approval, and every decision, including denials, is appended to an audit log. Denials are returned to the agent as results, so it can re-plan instead of crashing. This limits blast radius but does not prevent misuse inside allowed tools: an allowlisted read tool can still leak data, so pair it with argument validation, network egress limits and credentials scoped to the agent. The tools and thresholds in the snippet are illustrative.

```python
# A minimal agent tool gate: allowlist, per-task budget, human approval for writes, audit log.
import json
class Gate:
    def __init__(self, allow, budget, needs_approval):
        self.allow, self.left, self.needs = set(allow), budget, set(needs_approval)
        self.log = []
    def call(self, tool, args, approver=None):
        entry = {"tool": tool, "args": args}
        if tool not in self.allow:
            entry["result"] = "DENY: not allowlisted"
        elif self.left <= 0:
            entry["result"] = "DENY: budget exhausted"
        elif tool in self.needs and not (approver and approver(tool, args)):
            entry["result"] = "DENY: no human approval"
        else:
            self.left -= 1
            entry["result"] = "OK"
        self.log.append(entry)
        return entry["result"]

g = Gate(allow={"read_ledger", "draft_email", "post_payment"}, budget=3,
         needs_approval={"post_payment"})
plan = [("read_ledger", {"acct": 1}), ("shell", {"cmd": "curl x"}),
        ("post_payment", {"amt": 900}), ("draft_email", {}), ("read_ledger", {"acct": 2}),
        ("draft_email", {})]
for tool, args in plan:
    g.call(tool, args, approver=lambda t, a: a.get("amt", 0) < 500)
for e in g.log: print(json.dumps(e))
print("calls left:", g.left)
```
