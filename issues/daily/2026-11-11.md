### L1 · Estimate training compute with C ≈ 6·N·D, and why MoE uses active N

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~10 min

**Why today.** Baidu's ERNIE 5.5 Flash is a 280B-parameter MoE with 14B parameters active per token, so its training compute scales with 14B while its memory footprint scales with 280B. ([Baidu releases ERNIE 5.5 Flash Preview (280B MoE, 14B active, 1M context), promises open weights by Nov 25](https://finance.sina.com.cn/tech/digi/2026-11-11/doc-iniyixxz1868491.shtml))

Each training token costs about 2N FLOPs in the forward pass (one multiply-add per parameter) and about 4N in the backward pass (gradients with respect to activations and to weights), giving C ≈ 6·N·D for D tokens. In a mixture-of-experts model only the routed experts run per token, so N is the active count, which is why a 280B/14B MoE trains at roughly the cost of a dense 14B model. Memory does not shrink: all experts' weights, gradients and Adam moments must be stored, which here is several terabytes and forces expert parallelism. The rule ignores attention FLOPs (a 12·L·T·d term that matters at long context), router overhead and the communication cost of all-to-all expert dispatch, which is often the real bottleneck. Divide C by peak throughput times model FLOPs utilisation to get wall-clock accelerator time.

$$
C \approx 6\,N_{\text{active}}\,D, \qquad t \approx \frac{C}{\text{peak} \cdot \text{MFU}}
$$

```python
# Training compute for dense vs MoE: C ~ 6 * N_active * D  (illustrative numbers)
def train_flops(n_active, tokens):
    return 6 * n_active * tokens

def gpu_days(flops, peak=1e15, mfu=0.4):
    # peak ~1 PFLOP/s dense BF16 per accelerator (illustrative), mfu = achieved fraction
    return flops / (peak * mfu) / 86400

D = 20e12                      # 20T training tokens (illustrative)
configs = {
    "dense 280B":            280e9,
    "MoE 280B / 14B active":  14e9,
    "dense 14B":              14e9,
}
for name, n_act in configs.items():
    c = train_flops(n_act, D)
    print(f"{name:24s} C = {c:.2e} FLOPs  ~ {gpu_days(c):,.0f} accelerator-days at 40% MFU")
# Memory is set by TOTAL params; compute by ACTIVE params.
bytes_per_param = 2 + 4 + 4 + 4   # bf16 weights + fp32 master + Adam m, v
print(f"optimizer+weights state for 280B total: {280e9*bytes_per_param/1e12:.1f} TB")
```

### L2 · Write masked softmax attention from scratch, then sparsify it with a window

`AI-off fluency` · now 2.5 → target 4.0 · priority 1.50 · ~15 min

**Why today.** Baidu cites hybrid sparse attention as one of the ingredients behind ERNIE 5.5 Flash's 1M-token context. ([Baidu releases ERNIE 5.5 Flash Preview (280B MoE, 14B active, 1M context), promises open weights by Nov 25](https://finance.sina.com.cn/tech/digi/2026-11-11/doc-iniyixxz1868491.shtml))

Attention computes scores S = QKᵀ/√d, sets disallowed positions to −∞, applies a row-wise softmax and mixes the value rows. A causal mask lets position i see j ≤ i, so cost grows as T²/2. A sliding window keeps only the last w positions, cutting cost to about T·w, at the price that information from further back must travel through several layers. Hybrid schemes mix windowed or sparse layers with a few full-attention layers to keep long-range recall. Subtracting each row's maximum before exponentiating leaves the softmax unchanged but prevents overflow; the snippet shows outputs agree exactly while the window covers the whole prefix and diverge after that.

$$
\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}} + M\right)V,\quad M_{ij}\in\{0,-\infty\}
$$

```python
import math, random
random.seed(0)
T, d = 8, 16
X = [[random.gauss(0, 1) for _ in range(d)] for _ in range(T)]
W = [[[random.gauss(0, 1) / math.sqrt(d) for _ in range(d)] for _ in range(d)] for _ in range(3)]
mm = lambda A, B: [[sum(a * b for a, b in zip(r, c)) for c in zip(*B)] for r in A]
Q, K, V = (mm(X, w) for w in W)

def attention(allowed):
    out, rows = [], []
    for i in range(T):
        s = [sum(q * k for q, k in zip(Q[i], K[j])) / math.sqrt(d) if allowed(i, j) else -math.inf
             for j in range(T)]
        m = max(s)                                   # subtract max: stable softmax
        e = [math.exp(x - m) for x in s]; z = sum(e)
        p = [x / z for x in e]; rows.append(p)
        out.append([sum(p[j] * V[j][c] for j in range(T)) for c in range(d)])
    return out, rows

causal = lambda i, j: j <= i
window = lambda i, j: j <= i and i - j < 3           # sliding window of 3: a sparse pattern
full, P = attention(causal)
win, _ = attention(window)
print("rows sum to 1:", all(abs(sum(r) - 1) < 1e-12 for r in P))
print("scores computed: causal", sum(causal(i, j) for i in range(T) for j in range(T)),
      "| window", sum(window(i, j) for i in range(T) for j in range(T)))
print("max |full - window| per position:",
      [round(max(abs(a - b) for a, b in zip(full[i], win[i])), 3) for i in range(T)])
```

### L3 · Bound decode speed by memory bandwidth: tokens/s ≤ BW / bytes per token

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~10 min

**Why today.** Fractile raised $720M for inference chips that stack memory on logic to ease bandwidth limits, and MoE models such as ERNIE 5.5 Flash read only their active parameters per token. ([UK AI chip startup Fractile raises $720M at about $7B valuation, backed by Britain's Sovereign AI fund](https://techcrunch.com/2026/11/11/with-720m-round-britains-fractile-gets-a-leg-up-in-the-race-for-ai-chips/) · [Baidu releases ERNIE 5.5 Flash Preview (280B MoE, 14B active, 1M context), promises open weights by Nov 25](https://finance.sina.com.cn/tech/digi/2026-11-11/doc-iniyixxz1868491.shtml))

In autoregressive decoding at small batch, each new token requires reading every active weight from memory once, while doing only about 2 FLOPs per weight, far below the arithmetic intensity accelerators need to be compute-bound. Single-sequence speed is therefore bounded by bandwidth divided by bytes read per token (weights plus that sequence's KV cache). Lower precision and fewer active parameters (MoE) raise the bound proportionally, and so does more bandwidth, which is the case for on-die or stacked memory. Batching B sequences reuses each weight read B times, raising throughput until the FLOP limit is hit; the KV cache, which grows per sequence, does not amortise and eventually dominates.

$$
\text{tok/s} \le \frac{\mathrm{BW}}{N_{\text{active}}\, b + M_{KV}}
$$

```python
# Decode is memory-bound: each generated token must stream the active weights (+ KV cache) from memory.
# tokens/s per sequence <= bandwidth / bytes_read_per_token   (illustrative numbers)
def max_tok_s(active_params, bytes_per_param, bandwidth_Bps, kv_bytes=0):
    return bandwidth_Bps / (active_params * bytes_per_param + kv_bytes)

hbm = 8e12           # 8 TB/s, an HBM-class accelerator (illustrative)
```
