### 2 · OpenAI and Cisco open-source Shirudo, letting AI agents write eBPF shields for unpatched Linux systems

`I = 71.1` · Products & agents · US · OpenAI, Cisco, Isovalent · `CSCO`

OpenAI and Cisco released Shirudo, an open-source Linux runtime in which agents write small temporary eBPF programs ('shields'). Each shield blocks the specific behaviour a vulnerability depends on, so the system needs no reboot while the full patch is tested and rolled out. An operator must approve each shield, and shields are cryptographically signed. In a demo, Codex generated a shield that blocked 'Java4Shell' exploitation on a running Elasticsearch instance. Shirudo builds on Isovalent's Tetragon, is BSD-2-Clause licensed (BPF programs dual BSD/GPL), and needs Shirudo's kernel patches plus TPM 2.0 in production.

**Why it matters.** This is a frontier lab shipping defensive agent tooling at kernel level, aimed at the patch gap that AI-accelerated exploitation is widening. It also gives Cisco's Isovalent stack a role in agentic security operations.

**Key numbers.** BSD 2-Clause licence · Requires TPM 2.0 + kernel patches · Deep-dive webinar Dec 15

### L1 · Split an agent benchmark's variance into model, harness and noise

`LLM / agent evaluation` · now 2.5 → target 4.5 · priority 2.00 · ~15 min

**Why today.** ShellBench reports a median 45.7-point spread between models with the harness fixed, against only 6.2 points between harnesses with the model fixed, across 100 everyday tasks. ([ShellBench: best AI agent completes 62.5% of everyday tasks drawn from 10M+ real agent interactions](https://techcrunch.com/2026/11/24/even-the-best-ai-agents-struggle-with-everyday-life/))

Treat a models x harnesses score grid as a two-way layout: score = grand mean + model effect + harness effect + interaction/noise. Sums of squares of the row and column means tell you what share of the variation each factor explains, which is more robust than max-min spreads. Spreads are biased upward by noise: with 100 binary tasks a single run at 60% has a standard error of about 4.9 points, so a max-min across five harnesses can show 10+ points even when the true harness effect is small. Before claiming a harness 'matters', compare its effect with the binomial noise floor, rerun with seeds, or use paired tests on the same tasks. The snippet uses synthetic scores, not ShellBench data.

$$
SS_{model} = H\sum_m (\bar y_{m\cdot}-\bar y)^2,\quad SS_{harness} = M\sum_h (\bar y_{\cdot h}-\bar y)^2,\quad SE = \sqrt{p(1-p)/n}
$$

```python
# Two-way decomposition of agent-benchmark scores: model effect vs harness effect.
# Synthetic, illustrative scores only (not ShellBench data).
import random, statistics as st
random.seed(0)
models = {f"M{i}": random.uniform(20, 65) for i in range(8)}      # true model skill
harness = {h: random.gauss(0, 3) for h in "ABCDE"}                  # small harness offsets
n_tasks = 100
score = {}
for m, mu in models.items():
    for h, off in harness.items():
        p = min(max((mu + off) / 100, 0), 1)
        score[m, h] = 100 * sum(random.random() < p for _ in range(n_tasks)) / n_tasks
grand = st.mean(score.values())
m_eff = {m: st.mean(score[m, h] for h in harness) - grand for m in models}
h_eff = {h: st.mean(score[m, h] for m in models) - grand for h in harness}
ss_m = len(harness) * sum(v * v for v in m_eff.values())
ss_h = len(models) * sum(v * v for v in h_eff.values())
ss_tot = sum((v - grand) ** 2 for v in score.values())
print(f"share of variance: model {ss_m/ss_tot:.0%}, harness {ss_h/ss_tot:.0%}, "
      f"interaction+noise {1-(ss_m+ss_h)/ss_tot:.0%}")
spread_m = st.median(max(score[m, h] for m in models) - min(score[m, h] for m in models) for h in harness)
spread_h = st.median(max(score[m, h] for h in harness) - min(score[m, h] for h in harness) for m in models)
print(f"median spread across models (harness fixed): {spread_m:.1f} pts")
print(f"median spread across harnesses (model fixed): {spread_h:.1f} pts")
# Binomial noise floor: one run on 100 tasks at p=0.6 has SE ~ 4.9 pts
print(f"binomial SE at p=0.6, n={n_tasks}: {100*(0.6*0.4/n_tasks)**0.5:.1f} pts")
```

### L2 · Price an MoE: memory follows total parameters, decode speed follows active ones

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~12 min

**Why today.** Baidu's open ERNIE 5.5 Flash Preview is reported as a mixture-of-experts with 280B total and 14B active parameters per token. ([Baidu open-sources ERNIE 5.5 Flash Preview weights: 280B-parameter MoE, 14B active, Apache 2.0](https://www.ithome.com/1/031/501.htm))

In a mixture-of-experts model a router sends each token to a few experts, so per-token compute is about 2 FLOPs per active weight, while all experts must still sit in accelerator memory. A 280B/14B MoE therefore needs the memory footprint of a 280B dense model but has the per-token FLOPs of a 14B one. At small batch sizes decoding is memory-bandwidth-bound, and the ceiling is roughly bandwidth divided by bytes of active weights read per token, which is why MoEs decode fast. The idea breaks at large batches, where different tokens hit different experts and the whole weight set gets read anyway, and under expert-parallel sharding, where all-to-all communication and load imbalance between experts dominate. The bandwidth and HBM figures in the snippet are illustrative.

$$
C_{tok}\approx 2P_{active},\qquad M_{weights}= P_{total}\cdot b,\qquad \text{tok/s}_{\max}\approx \frac{BW}{P_{active}\cdot b}
$$

```python
# MoE serving arithmetic: memory scales with TOTAL params, per-token compute with ACTIVE.
# 280B total / 14B active matches the reported ERNIE 5.5 Flash headline figures;
# the dense comparison and bandwidth numbers are illustrative.
def serve(total_b, active_b, bytes_per_w=1.0, hbm_gb=141, bw_tbs=4.8):
    weights_gb = total_b * bytes_per_w                # FP8 weights ~1 byte each
    gpus = -(-weights_gb // (hbm_gb * 0.8))           # leave 20% HBM for KV cache
    flops_tok = 2 * active_b * 1e9                    # ~2 FLOPs per active weight
    # Decode at batch 1 is bandwidth-bound: read the active weights once per token
    tok_s = bw_tbs * 1e12 / (active_b * 1e9 * bytes_per_w)
    return weights_gb, int(gpus), flops_tok, tok_s

for name, tot, act in [("MoE 280B/14B", 280, 14), ("dense 70B", 70, 70), ("dense 280B", 280, 280)]:
    w, g, f, t = serve(tot, act)
    print(f"{name:13s} weights={w:5.0f} GB  GPUs(141GB)={g}  "
          f"GFLOPs/token={f/1e9:5.0f}  batch-1 decode ceiling~{t:5.0f} tok/s per GPU-bandwidth")
```
