### L1 · Write the knowledge-distillation loss and see what temperature does

`LLM internals & post-training` · now 2.5 → target 4.5 · priority 2.00 · ~15 min

**Why today.** Reuters reports that Chinese groups are distilling US frontier models at industrial scale to train smaller domestic models, so it is worth knowing exactly what a distillation objective optimises. ([Reuters: Chinese labs increasingly distil US frontier models to train domestic rivals as chip curbs bite](https://bworldonline.com/technology/2026/11/17/794447/china-taps-us-ai-models-to-train-homegrown-rivals-as-chip-curbs-bite/))

Classic distillation trains a student on a mix of the hard-label cross-entropy and the KL divergence from the teacher's temperature-softened distribution. Raising T flattens the teacher's softmax and exposes the relative probabilities of wrong classes (the 'dark knowledge'), which carry far more bits per example than a single label. The T^2 factor offsets the 1/T^2 shrinkage of the soft-target gradients, so the two terms stay on comparable scales as T changes. With LLMs, API-only distillation usually sees just sampled text, not logits, so it reduces to sequence-level SFT on teacher outputs and loses most of that dark knowledge. Run the snippet and watch the teacher distribution flatten and the soft term grow as T rises.

$$
\mathcal{L} = \alpha\,\mathrm{CE}(y, \sigma(z_s)) + (1-\alpha)\,T^2\,\mathrm{KL}\big(\sigma(z_t/T)\,\|\,\sigma(z_s/T)\big)
$$

```python
import math
# Knowledge distillation loss (Hinton et al., 2015) on one example. Illustrative logits only.
teacher = [6.0, 2.5, 2.0, -1.0]          # teacher logits over 4 classes
student = [3.0, 2.8, 0.5, 0.0]           # student logits
label = 0                                # hard label

def softmax(z, T=1.0):
    m = max(x / T for x in z); e = [math.exp(x / T - m) for x in z]; s = sum(e)
    return [x / s for x in e]

def kl(p, q):
    return sum(pi * math.log(pi / qi) for pi, qi in zip(p, q) if pi > 0)

ce = -math.log(softmax(student)[label])
for T in (1, 2, 4, 8):
    pt, ps = softmax(teacher, T), softmax(student, T)
    soft = T * T * kl(pt, ps)            # T^2 keeps gradient scale comparable across T
    loss = 0.5 * ce + 0.5 * soft
    print(f"T={T}: teacher probs={[round(p,3) for p in pt]}  soft KL*T^2={soft:.3f}  total={loss:.3f}")
```

### L2 · Measure an earnings-day abnormal return with a market-model event study

`Domain AI (finance, health)` · now 3.5 → target 4.5 · priority 0.70 · ~15 min

**Why today.** Nvidia beat on revenue and guidance and rose about 2-3% after hours, on a day the Dow fell 849 points, so separating the stock's own news from the market move is the right question. ([Nvidia's Q3 revenue rises 103% to $115.8B and it guides to $130B in its first report under interim CEO Kress](https://nvidianews.nvidia.com/news/nvidia-announces-financial-results-for-third-quarter-fiscal-2027) · [Dow falls 849 points and chip stocks slide again before Nvidia results; Samsung and TSMC drop about 5% in Asia](https://finance.yahoo.com/markets/live/stock-market-today-tuesday-november-17-dow-sp-500-nasdaq-nvidia-earnings-retail-sales-143848454.html))

An event study fits a market model r_s = alpha + beta r_m + e by OLS over an estimation window that ends before the event. The expected return on day 0 is alpha + beta times the market's move, and the abnormal return (AR) is the realised return minus that. Dividing AR by the residual standard deviation gives a rough t-statistic. A high-beta stock that rises on a down day therefore has an AR well above its raw return. The method breaks when the estimation window is contaminated by other events, when beta is unstable (as in a scandal-driven slide), or when the event is partly anticipated. Summing ARs over a few days gives the CAR this repo's market panel reports. The data in the snippet are synthetic.

$$
AR_0 = r_{s,0} - (\hat\alpha + \hat\beta\, r_{m,0}),\qquad t \approx AR_0 / \hat\sigma_\varepsilon
$$

```python
import random
# Market-model event study: abnormal return on an earnings day. Synthetic data, illustrative only.
random.seed(1)
n = 60                                       # estimation window (sessions)
mkt = [random.gauss(0.0004, 0.010) for _ in range(n)]
stk = [0.0005 + 1.8 * m + random.gauss(0, 0.018) for m in mkt]   # true beta 1.8

mx, sy = sum(mkt) / n, sum(stk) / n
beta = sum((m - mx) * (s - sy) for m, s in zip(mkt, stk)) / sum((m - mx) ** 2 for m in mkt)
alpha = sy - beta * mx
resid = [s - alpha - beta * m for m, s in zip(mkt, stk)]
sigma = (sum(e * e for e in resid) / (n - 2)) ** 0.5

event_mkt, event_stk = -0.010, 0.025          # hypothetical day 0: market -1.0%, stock +2.5%
ar = event_stk - (alpha + beta * event_mkt)
print(f"alpha={alpha:.4%} beta={beta:.2f} sigma={sigma:.2%}")
print(f"expected={alpha + beta * event_mkt:.2%}  AR={ar:.2%}  t={ar / sigma:.2f}")
```

### L3 · Separate parameter count from per-token compute in a looped transformer

`DL model training` · now 3.0 → target 4.5 · priority 1.35 · ~10 min

**Why today.** SenseTime's Loop-9B runs its shared middle layers twice, so 32 physical decoder layers perform 56 layer computations, which separates model size from compute per token. ([SenseTime releases open-weight SenseNova Loop-9B, a looped 9B model with 512K context; Cambricon adds day-0 support](https://www.ithome.com/1/028/534.htm))

In a standard transformer, forward compute per token is about 2N FLOPs for N weights, because each weight is used once. Looping a block of layers reuses the same weights, so FLOPs scale with the number of layer passes while parameter count, memory and download size stay fixed. A looped model therefore sits off the usual parameter-based scaling curves: it buys depth with compute instead of with memory, which helps when GPU memory, not arithmetic, is the binding constraint. The cost is less capacity than an unlooped model of equal depth and, often, harder training stability. The snippet uses illustrative sizes, not SenseTime's configuration.

$$
C_{\text{tok}} \approx 2\,(L_{\text{phys}} + L_{\text{shared}}(k-1))\,P_{\text{layer}},\qquad N = L_{\text{phys}} P_{\text{layer}}
$$

```python
# Looped (weight-shared) decoder: parameters vs per-token compute. Illustrative sizes, not any real model's config.
d, ff_mult, vocab = 4096, 4, 150_000
layer_params = 4 * d * d + 2 * ff_mult * d * d       # attention (Q,K,V,O) + 2-matrix MLP, no biases
embed = vocab * d

def model(physical, loops, shared):
    """physical layers; the `shared` middle layers are run `loops` times."""
    params = physical * layer_params + embed
    executed = physical + shared * (loops - 1)
    flops_tok = 2 * executed * layer_params + 2 * embed   # ~2 FLOPs per weight use (forward)
    return params, executed, flops_tok

for name, cfg in [("plain 32", (32, 1, 0)), ("loop 24 shared x2", (32, 2, 24)), ("plain 56", (56, 1, 0))]:
    p, e, f = model(*cfg)
    print(f"{name:18s} params={p/1e9:5.2f}B  layer passes={e:2d}  GFLOPs/token={f/1e9:6.1f}")
```
